# Documentation

Ground documentation in the current implementation and executable commands; do not infer behavior from intent alone. Identify the audience and document prerequisites, inputs, outputs, errors, and examples that a reader can actually use. Keep existing terminology and document structure where possible. Update only affected documentation, verify commands and paths against the repository, and call out any behavior that remains undocumented because it could not be validated.
